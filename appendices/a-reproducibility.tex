\section{Measurement Contracts}
\label{sec:a-e1-protocol}

E1 reports the median of five round throughputs, each computed as total
queries divided by elapsed host-to-host time. A round normally uses 24
calls; a warm-up threshold reduces this count at 274 points. The Python
decision interval includes first-call conversion and validation, so it
differs from steady-state latency. Resource reuse, preallocated outputs,
pinned input staging and timed int8 query quantisation improve
comparability; output-memory types and Python/C++ boundaries still differ.
Device-only baseline timing is auxiliary to this common call boundary.

The 369 baseline repeat-call identifier flags include tie-order changes
and do not alone exclude points. The earlier count of 401 additionally
includes cross-protocol disagreements; the exact union and method counts
are in the expanded protocol. JHQ does not populate the same flag.
Cold-build train/add timers exclude object construction, host QR and
constructor library warm-up. Construction diagnostics sample device used
memory, including context, every 20\,ms; synchronised one-buffer phase
runs remain separate from normal pipeline measurements.

\section{Budget Harness Contract}
\label{sec:a-budget-contract}

The campaign explicitly sets the eight-point grid beginning at 200,
overriding a fallback string beginning at 100. Even query indices form
the 500-query calibration pool; odd indices form the 500-query held-out
pool, or 499 for Stella. Each $S\in\{32,64,128\}$ has 64 seeded draws
without replacement. The initial warm-up traverses all queries, while
its outputs and GT remain outside the agreement decision. Scan-schedule
calibration uses separate database pseudoqueries.

Each fixed arm receives one warm-up and three timed calls. Calibration
times reference/candidate searches and the $O(Sk^2)$ host agreement
comparison with graph capture bypassed; prior $O(Sd)$ sample gathering
and separate scan calibration are excluded. The logged p95 is sorted
index $\lfloor0.95(64-1)\rfloor$. The helper returns a grid index and
leaves the last tested multiplier installed: callers must apply
\texttt{set\_alpha(A[index])}. Selected-arm rates in the original campaign
reuse already timed fixed arms.

Original enumeration checks cover 2,304 subsampled decisions, excluding
the twelve FULL calls. Supplementary enumeration also matches all twelve
FULL decisions. At FULL size, two Vogue cells use four groups and ten
cells use distance-only selection; common cutoff ordering remains the
condition for a general binary-search guarantee. Finite-pool prediction
models uniform subsets and requires per-query counts invariant to subset
membership and position under the relevant execution regime. All 18,432
sampled grid counts equal their recorded full-pool subset sums. Mapping
acceptance to GT-loss crossings additionally uses the held-out fixed-arm
quality labels. These checks establish the recorded cases, rather than
unknown query-population quality.

\section{Supplementary Evidence}
\label{sec:a-supplement}

A1 separates first-read, normal
warm-input and synchronised phase runs on six datasets; five-build recall
is measured at fixed 128 probes. C1 checks four complete database layouts
and sampled re-encodings. Its FP64 norm checks use the stored rotation
matrix, rather than actual GPU rotation outputs. A3 checks every OpenAI
query row and 10,299 strided base rows; original entity-ID mappings are
absent.

A2 extracts the recorded executable's sm\_80 PTX and reassembles it with
CUDA 13.0.88 \texttt{ptxas} for sm\_120. The observed 64-bit bound read
and atomic-min publication use an aligned query-key array with eight-byte
stride. The argument uses PTX alignment, scope and proxy semantics;
toolkit SASS corroborates it without supplying the driver's loaded JIT
code.

D alternates v69/v72 over the E1 OpenAI grid, reusing TF32-trained states
and changing add/query GEMMs. Its baseline denominators remain archived
E1. The later contemporaneous T1 anchors are reported separately in
\cref{sec:b-precision-anchors}. Neither experiment constitutes FP32
retraining.

B reproduces the original \texttt{srand(12345)} decisions and adds
per-query curves, FULL enumeration and direct reuse traces. Direct
timing uses a separate seeded sequence, five rotated-policy rounds and
500 repetitions of the held-out batch. It includes gathering,
calibration, budget installation and first-batch graph setup; construction,
schedule calibration and warm-up remain outside that interval. Schedule
calibration startup costs are separately reported.

\section{Strict Selection, Small Batches and Artifact Access}
\label{sec:a-t4-t5}

T4's v73 source matches v71 after removing its two debug-export blocks.
CPU sorting consumes GPU-produced primary and retained refined scores.
The exported-score equality check covers returned valid primary entries;
the padding counter checks valid-entry counts. Natural short pools are
covered, while deliberately empty or adversarial lists remain separate
tests. Table-form comparisons align candidate positions at 128 probes,
$\alpha=100$, 256 queries, shared bounds enabled, $\gscan\in\{0,2\}$ and
$\glut\in\{1,2,4,8\}$. Temporary candidate dumps were deleted: retained
JSONL/stdout and LUT summaries support the reported finite-case counts.
The same-model Vogue cross-process discrepancy remains unexplained;
within-run T4 selection checks address a different question.

T5 partitions queries into fixed small batches and includes staging,
transfers, applicable int8 query quantisation and synchronisation. Each
point is the median of five round throughputs; null-call costs remain
included. JHQ/CAGRA reuse E1 grids and RaBitQ has its own recorded sweep.
Numeric JSON supplies recall thresholds. Interpolated estimates retain
qualifying endpoints below the minimum frontier recall; strict measured
thresholds remain separate. Python/C++ interfaces and warm-up policies
differ, and these measurements do not establish concurrent-service latency.

GPU reproduction requires original vectors, matching trained states and
builds, and the specified environment. \Cref{sec:b-artifacts} identifies
which materials are available.
