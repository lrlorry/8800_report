查询级扫描仅为每条查询暴露一个 block。分组扫描将候选划分给多个 block 后合并保留结果，处理 GPU 选择问题\cite{johnson_gpu}。精确性针对已计算主码分数，路由与表示仍具有近似性。

\subsection{候选划分与确定性顺序}

对固定查询，按探针顺序拼接选中的倒排列表，得到 $n_c$ 个候选出现位置。假设每个被访问数据库行只出现一次，搜索期间索引保持不变。对 $\gscan\in\{1,2,4,8\}$，block $(q,j)$ 负责区间
\begin{equation}
 U_j=\left[\left\lfloor\frac{j n_c}{\gscan}\right\rfloor,
              \left\lfloor\frac{(j+1)n_c}{\gscan}\right\rfloor\right),
 \qquad j=0,\ldots,\gscan-1.
 \label{eq:5-partition}
\end{equation}
这里的区间表示相应候选，而不是它们的数据库 ID。设备端依据路由得到的候选数计算区间端点。各组候选数最多相差一个；一个较长的列表可以跨越组边界。这种划分平衡的是候选数量，而平均分配列表数量不一定能达到同样效果。每个线程通过探针前缀偏移找到自己的第一个列表，在扫描区间时向前移动列表游标。此阶段不读取残差码。

选择使用的 key 为
\begin{equation}
 K_q(x)=\bigl(\primarydist(q,x),p(x)\bigr),
 \qquad
 (a,p)\prec(b,r)\iff a<b\ \text{or}\ (a=b\ \text{and}\ p<r),
 \label{eq:5-primary-key}
\end{equation}
其中 $p(x)$ 是固定倒排存储中的物理行位置。它在该查询的候选中唯一，不依赖原子追加的先后顺序，也不是最终结果处理并列时使用的数据库 ID。当分数不含 NaN 时，这一定义为不同候选建立全序。局部比较和合并决策都使用相同顺序。要使选择不受划分方式影响，还要求各条比较路径为同一候选计算出相同的分数；排序规则本身不能消除浮点评分差异。

\subsection{精确局部保留与全局覆盖}

用 $\operatorname{Top}_c(V)$ 表示将 $V$ 按 $K_q$ 排序后最前面的 $\min(c,|V|)$ 个候选，其中 $c=\max\{k,\lceil\alpha k\rceil\}$。每个独立组保留完整的局部 top-$c$，而不是分得一个 $c/\gscan$ 配额。这一区别不可省略：当 $c=4$、组数为二时，四个全局优胜候选可能全在同一组。如果每组只保留两个，即使总容量为四，仍会丢掉全局优胜候选。

\begin{lemma}[局部缓冲区保留]
\label{lem:5-buffer}
设 $V_t$ 为一个 block 截至 chunk $t$ 已评分的候选，$B_t$ 为该时刻完成压缩或过滤后的有效缓冲区。假设完整 key 固定、追加容量充足、压缩精确保留 top-$c$。令 $\beta_t$ 为截至该时刻读到的全部完整共享界的最小值，包含初始顶哨兵，则
\begin{equation}
 \operatorname{Top}_c(V_t)\cap\{x:K_q(x)\preceq\beta_t\}
 \subseteq B_t.
 \label{eq:5-buffer-invariant}
\end{equation}
关闭共享界时，界始终为哨兵，缓冲区包含整个已扫描前缀的 top-$c$。
\end{lemma}
\begin{proof}
空前缀满足不变量。新候选若未通过局部准入阈值，则已有 $c$ 个保留 key 排在它之前；这些前驱在之后的前缀中仍存在。共享界拒绝的候选均在 $\beta_t$ 之后。旧候选若已不属于前缀 top-$c$，前缀增长也不会改善其名次。因此，每个符合界的新前缀优胜候选，要么已经保留，要么获准追加。精确压缩不会丢弃它：在整个前缀中排在它之前的成员少于 $c$，缓冲区内也如此。过滤仅删除读到的界之后的 key。对追加、压缩及过滤归纳即得结论。若读取可能返回不同的旧发布值，必须使用历史读取的最小值表述不变量。
\end{proof}

\begin{proposition}[覆盖与截断合并]
\label{prop:5-local-coverage}
在固定 key 和共同全序下，设 $U$ 为已访问候选全集，$V$ 为任一保留子集。若 $\operatorname{Top}_c(U)\subseteq V\subseteq U$，则 $\operatorname{Top}_c(V)=\operatorname{Top}_c(U)$。有序列表两两合并且每轮截取前 $c$ 项保持这一结论。特别地，对互不相交的分组，有
\begin{equation}
 \operatorname{Top}_c\!\left(\bigcup_j U_j\right)
 =\operatorname{Top}_c\!\left(\bigcup_j
                    \operatorname{Top}_c(U_j)\right).
 \label{eq:5-topc-union}
\end{equation}
候选全集不足 $c$ 时，结论同样成立。
\end{proposition}
\begin{proof}
每个全局优胜候选都在 $V$ 内，其余 $V$ 中的成员均排在全局优胜候选之后，因此从 $V$ 选择可恢复全局结果。对独立分组这一特例，设 $x$ 同时属于全局 top-$c$ 和组 $U_j$。全局排在 $x$ 之前的候选少于 $c$ 个，因此组内也少于 $c$ 个。于是 $x\in\operatorname{Top}_c(U_j)$，局部结果并集包含全部全局优胜候选。整个全集不足 $c$ 时，所有成员均保留。

对于合并，两个有序列表的前 $c$ 项就是二者并集的 top-$c$。被截去的候选在该并集中已经有至少 $c$ 个前驱，不可能再进入任何更大并集的 top-$c$。对合并树的各轮归纳即可得到结论。
\end{proof}

CUDA 实现在共享内存中维护容量为 $C_{\rm buf}$ 的 key 对缓冲区。扫描 block 含 $T_{\rm blk}$ 个线程，$C_{\rm buf}$ 为二的幂且满足 $C_{\rm buf}\geq c+T_{\rm blk}$。压缩操作通过 bitonic 网络排序，保留至多 $c$ 个有效条目；当有效条目达到 $c$ 个时，将最后一个保留 key 记为局部阈值。在此之前，阈值是排在所有有效 key 之后的哨兵。两次压缩之间，仅追加排在阈值之前的候选。即使后续候选继续到来，阈值对应的 $c$ 个见证候选仍使它成为已扫描前缀中最优 $c$ 项的安全上界。

每个 chunk 最多追加 $T_{\rm blk}$ 项；可能越界前先压缩至至多 $c$ 项，
$C_{\rm buf}\geq c+T_{\rm blk}$ 保证下一块容量。这满足\Cref{lem:5-buffer}的容量前提，
无需逐线程配额。共享时，\Cref{prop:5-shared-bound}保证已读阈值不小于全局第 $c$ 个 key，
再由缓冲区引理与覆盖命题保证过滤及合并保留全局优胜候选。

另一种方案是先将全部 $n_c$ 个分数／位置对写出，再调用独立选择器。这保持相同目标，但增加一个 $O(n_c)$ 中间数组及其写入。这里将打包主码的评分直接送入有界局部缓冲区，以重复局部排序换取 $O(\gscan c)$ 规模的中间输出。基于寄存器的选择也是已有的 GPU 设计\cite{johnson_gpu}；本轮实验以归档参考路径评估选定的扫描变体。

\subsection{合并实现、存储与边界情况}

当 $\gscan>1$ 时，每条查询由一个 256 线程的 block 执行 $\log_2 \gscan$ 轮两两合并。有效长度为 $a,b$ 的一对列表输出 $\min(c,a+b)$ 个 key。Merge Path 将输出划分为连续的线程片段：先二分查找每个片段对应的输入偏移，再由该线程顺序合并自己的片段\cite{gpu_merge_path}。所有比较都遵循\cref{eq:5-primary-key}，各轮之间通过 block 屏障同步。\Cref{fig:5-global-selection} 展示了截断不变量。除划分查找与同步工作外，合并树全部内部节点合计最多输出 $c(\gscan-1)$ 个 key 对。

两个全局分数／位置工作区的容量分别为 $[b_{\rm cap},\gscan,c]$ 和 $[b_{\rm cap},\gscan/2,c]$，在各轮间交替使用。分数和位置各占四字节，因此二者的总载荷为
\begin{equation}
 S_{\rm pairs}=8b_{\rm cap}c\left(\gscan+\frac{\gscan}{2}\right)
 \quad\text{bytes},\qquad \gscan>1.
 \label{eq:5-group-workspace}
\end{equation}
各组计数还需要 $4b_{\rm cap}\gscan$ 字节；配置共享界存储时另需 $8b_{\rm cap}$ 字节。这些空间位于最终保留数组及其他搜索工作区之外。分配容量在 graph capture 之前增长，之后保留复用，因此以后选择较小的 $\gscan$ 不一定释放预留显存。合并只在共享内存中保存列表长度，而不存放全部 $\gscan c$ 个 key。

局部有效前缀由计数界定，而不是仅依靠哨兵分数。压缩时，排序缓冲区填充 $(+\infty,\mathrm{INT\_MAX})$；有效位置必须小于这个保留位置。空组计数为零。最终保留数组将未使用槽位填为 $(+\infty,-1)$，残差精排跳过负位置。这两种哨兵用途不同：负位置填充项不能作为有效 key 参与合并。当 $\gscan=1$ 时，直接写最终保留数组，无需合并。

较早的查询级路径由实现标签 $\gscan=0$ 选择，表示每条查询一个 block，而不是零个 block。其默认主码选择按分数精确，但仅比较距离的截断规则可能在并列处保留与完整 key 路径不同的成员。有损的 \texttt{K\_LOCAL=4} 替代路径需要在允许该路径的构建中通过 \texttt{JHQ\_EXACT\_TOPCK=0} 开启；paper-faithful 构建强制使用精确选择。它不是被测默认路径。对仅比较距离的路径，缓冲区论证使用全预序：最终压缩后，保留所有严格小于前缀第 $c$ 小距离的候选，并在该距离处保留足够成员以填满 $\min(c,|V_t|)$ 个槽位。被拒绝的距离已有 $c$ 个距离不更大的保留见证；精确距离排序在每轮压缩保持这一名次性质。并列成员身份不要求唯一。
