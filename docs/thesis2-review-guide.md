## 2. 从读者角度检查，而不是只检查句子是否“学术”

读者可以有 ANN、数据库或计算机研究背景，但不应被默认已经读过 JHQ 原论文、项目源码和实验日志。

每一节依次回答：

1. 这一节要解决什么问题，为什么会出现？
2. 这里的对象、输入、输出和必要符号是什么？
3. 方法怎样解决问题，为什么这样设计？
4. 什么推导或证据支持它，成立条件是什么？
5. 读完后，读者得到什么认识，怎样接到下一节？

不要一上来报实现方案、内部术语或实验数字，再让读者自己推断问题。也不要每节机械增加一段预告和一段总结；过渡应当完成真实的逻辑连接。

### 段落组织的具体要求

- 不要一两句话就另起一段，连续列出互不承接的“备注”。同一主题的条件、做法与影响应归在一起。
- 也不要把不同主题简单拼成大段。合并前先确定这一段究竟回答什么。
- 显示公式前说明对象与用途，公式后解释结论或实现意义；不要靠公式代替过渡。
- 章节开头不能因删图而直接剩下 “First, …”。需要自然的引导句。
- 第 3.3 节的四段结构是一个实例，**不是所有小节必须写四段**。

### 第三章后续核对补充

- 简化取点规则时，保留插值容差与严格实测门槛的区别、对数吞吐插值和小 batch 的达标端点规则；不要用一句“测量范围外都不报告”掩盖已明确允许的端点取值。
- “校准不用 GT”不等于“全部实验只用 GT 计算召回率”：使用标签的诊断性预算对照仍需据实交代。
- “共同评分定义”不等于“所有浮点分数逐位相同”。涉及 LUT 分解或归约顺序时，保留数值差异与并列规则的核对。
- 多个实验代号可用简短导航表说明目的和结果位置；章节位置使用交叉引用。论文中的易混代号可改名，但需保留与原始记录的一次对应，不改写历史实验名称。

### 方法章与统计章节的审核补充

- 机制先交代 GPU 上的问题，再说明输入、做法、正确性条件和资源代价；结果引用放在真正需要验证收益的位置，不机械地给每小节套相同开头和收尾。
- 引理／命题前用短句解释它具体保住了什么。完整键、有效候选、共享界、哨兵、过时读取等对象先解释再进入证明；不要求反复使用 “In words” 标记，正式陈述与证明保持原文。
- 配置默认值与评测显式启用的设置集中到实验协议；指令名等细节可放脚注，决定证明是否成立的内存操作、域和证据范围不能随之删掉。
- `arm`、`draw`、`cell` 优先写成固定预算、校准查询样本和配置；FULL 首次解释为全池校准。正式证明、存档名称及表中既有符号按其原义保留。
- 统计公式先说明计数对象和要回答的问题，再陈述假设及结论；区分查询级事件、结果槽位、固定查询池抽样和未来查询总体，不把一种模型的概率结论套到另一种口径。
- 概括同类限制、删除重复免责，但不设“每节只能一处限定”之类机械配额。样本内界、二分成立条件、全池未被定理覆盖的路径和校准复用条件，各在需要它们的位置交代。
- 比较收益必须同时说明保持了什么、改变了什么。例如，按字打包降低代码读取操作数，不自动证明访存事务利用率；四／八组 LUT 的表空间比两组更少，但还要比较查表与合并成本。
- 充分条件不应压成无条件的 “exact”：最终选择仍要求足够的有限有效条目；分组选择的共同全序不等同于单 block 的任意截断并列；浮点重关联也不能笼统写成“只差最后一位”。
- 复用成本先定义计时边界和时间变量，再推回本条件。按所选预算查表平均得到的 QPS 与连续运行的直接吞吐分别报告，不将平均 QPS 的倒数当作平均时间。

## 4. 内容保留、压缩与删除的标准

| 内容 | 处理原则 |
|---|---|
| 必要定义、真实贡献、关键推导、证明前提、独有结果、引用与归属 | 保留；难懂时解释或重新组织 |
| 决定结论是否成立的实现条件 | 保留，并说明它和论证的关系 |
| 编译目标、版本、预热次数等复现设置 | 集中放在配置或协议位置；其他地方不要反复铺陈 |
| 内部函数名、文件路径、提交号、排错过程 | 只有对理解或复现确有必要时才进入正文；不要把工作日志写进论文 |
| 重复协议、紧邻图表的重复说明、无信息的收尾 | 合并、交叉引用或删除 |
| 同义的无标签公式、没有必要的演示算例 | 确认没有引用或推理依赖后可删除；保留主要定义和有用推导 |
| 限定语与负面结果 | 保留影响判断的内容，集中讲清；删除每节结尾重复的免责式句子 |
| 未核实的原因或数据 | 不补猜测；需要实验的登记到现有补证清单 |

- 原有数学内容不是全部不可动；第 3.3 节已合法删除重复的调用计时显示公式和 `(1,1,10) ms` 演示，同时保留吞吐公式。
- 不能把实测现象改写成一般定理，也不能用更多公式掩盖条件缺失。
- 学校建议、模板习惯、正式课程要求要区分；不要把自制标题或模板中的可选安排说成必交要求。
- 个人贡献以作者确认的事实为准。技术贡献表与个人角色说明避免重复，必要的来源、合作与 AI 协助披露如实保留。

## 6. 已经明确的事实边界

以下内容在文字压缩中容易被改错，后续必须核对：

- **精确性对象**：原始向量距离、primary score、refined score、候选选择和 GT recall 各有不同含义。“选择精确”不能写成 ANN 返回了精确原向量近邻。
- **排序与并列**：分组路径使用完整键；单 block 路径在距离并列截断处可能选择不同候选。物理位置与数据库 ID 的作用不能混淆。
- **LUT 分解**：实数运算下恒等，不等于 FP32 分数或最终 ID 逐位不变。T4 的实际差异必须保留。
- **TF32**：v69 的两个高维 OpenAI 数据集实际使用 TF32；FP32 复核复用 TF32 训练模型，不能描述为独立 FP32 重训练。
- **显存**：常驻量、临时分配、构建峰值、索引增量、进程总量和扣背景后的净值不同。JHQ 净值不能简写成只扣 CUDA context。
- **构建峰值**：不同时存在的缓冲区不能相加作为同时峰值；采样峰值也不保证捕获所有短暂分配。
- **时序与噪声**：未锁频的原因没有记录，不编写云服务器权限等理由。五轮结果不自动建立统一的“几个百分点都算持平”规则。
- **协议范围**：E1 的五轮测量规则不能套到只测三次或只有单次汇总的其他实验。
- **容量与比较**：不能因 FP32 预计装不下就写成实测 OOM；压缩基线可放入大数据集时，不能说“只有 JHQ 能放下”。
- **批量范围**：大 batch 的优势不能推广到小 batch、高 recall；正文实测负结果保留。
- **校准范围**：参考输出一致性、有限池上的观测、相对最佳已测预算的损失、未来查询的 GT recall 保证不能混写。
- **统计假设**：查询独立同分布不等于结果槽位独立；小样本、全池、二分与枚举的证据范围要讲清。

- 图内标签用已介绍的对象和直白措辞；新符号就近定义。不放 T4 等内部实验代号。机制图中的实验结果通常留在结果章；确实用于解释设计取舍的容量等数字可保留，但必须说明是解析估计、实测值还是假设情形。
- 连线必须表达真实的数据流或操作。不同 lane、线程组或候选独立处理时，各画自己的处理和输出；只有确实发生归约、合并或共享更新时，才汇聚箭头。多个数组共用位置索引时，优先使用对齐和高亮列，避免用多路折线穿过文字。
- 循环、条件和终止过程要可读。逐 chunk 扫描需画出返回下一 chunk 的路径和最终输出；拒绝分支就近放置。共享状态独立画框，读／写箭头明确区分并说明图例；发布条件和严格／非严格比较不得在简化时丢失。
- 图要解释设计差别及其理由，而不只是罗列步骤。例如，一遍／两遍建库的差别在临时副本容量，打包读取的差别在每 lane 如何取得编码。先核对代码与证据，再决定能画出什么收益。
- 通用协议图用各方法都适用的标签；缩写在图注或首次使用处解释；控制框高、换行和实际印刷字号。

- 删除反复出现的空泛免责句；解释图所必需的技术边界仍要保留在紧邻正文中。不能把“实数算术恒等”改成“FP32 逐位相同”，把“主码评分数量固定”改成“整个扫描成本不变”，或把不同时存活的显存分配相加。

## 10. 历史基线与结论章的补充规则

- 区分“从未做过比较”“已有历史比较”和“当前评测版本尚无匹配实验”。历史结果能回答量级问题，但不能直接变成当前版本的硬件加速比。CPU 对 GPU 的运行时比较，与 CPU 对 GPU 分数排序的正确性参考，是两类证据。
- 核对生成最终图的实际脚本、默认日志、线程数、参数范围及插值方式，不能只凭图例或较早的 provenance 说明推定。历史 CPU 图实际使用 `cpu6.log`；只有 Vogue 和 OpenAI-3072 有 16／32 线程包络，其余两项只有 32 线程。
- 相同召回率的前沿比较不等于相同训练索引的硬件比较。独立码本、不同列表数、旧 GPU 版本和重复计时不足应在历史结果附近集中说明；不能只凭 CPU 多线程就声称整个比较“保守”。
- 结论章先正面回答研究问题，再解释最有意义的证据和实际作用。RQ 名称与引言对应，不使用 FULL、cells、crossings 等未就地解释的代号，不用斜杠把不同条件和比值挤成一句。
- 从结果中挑关键证据，不把消融表逐项重抄，也不把不同基线下的提升相乘。使用与正文一致的显存边界、质量参照和 batch 条件。
- 未来方向要由已识别的瓶颈或证据边界引出，并交代怎样评价；已经完成的补证不能重新包装成尚未开展的工作。未来方向的数量不作为写作目标。

## 11. 讨论章与补充实验的证据规则

- 讨论应解释设计取舍与实验对研究问题的意义，避免重新搬运第 7 章的整套结果。构建峰值、索引常驻、选择正确性和 ANN 召回质量需要分开解释。
- 将数学分析、离线回放、成本模型、独立 GPU 内核测量、端到端 GPU 搜索测量分清。旧版数据不得混进当前系统前沿；模型估算不能写成已运行的 GPU 控制器性能。
- 表示实验同时改变主码、残差、质心或训练态时，明确哪些因素一起变化。一个数据集的干预收益不能解释全部跨系统排序，也不能从三个相关数据点推成普遍因果规律。
- 中心化在实数算术中保持原始 L2 距离，但不保证有限码长表示的召回率上限或校准预算总会改善。应同时检查较低预算收益和较高预算的质量损失。
- 安全剪枝界除了证明覆盖条件，还须检查实际选择性、评估成本与浮点实现的舍入安全。残差坐标包围盒必须与主码重建一起还原到正确坐标后，才能用查询距离构成下界。
- 调度规则的局限应依据实际工作区间解释。分组不仅服务小 batch，也可能改善大 batch 的负载不均；候选数离散程度不能代替候选总量。
- 未来方向写明动机、待检验假设、匹配对照和评价指标。残差卸载只能推断为容量研究方向，不能在主码和路由存储尚未核算时承诺十亿规模单卡运行。
- 部署建议限于已测 recall／batch／显存条件，不把“0.97 处领先”扩大为“所有低于 0.97 的区间都领先”。稳定查询池上的 500 查询工作点是有条件的起点，不是通用生产配置。

## 12. 实验结果章的补充审核规则

- 结果章先给带条件的发现，再给图表证据和必要边界；方法章仍先说明问题与机制。章首提供 RQ 与结果位置的对应，不为统一形式机械新增重复总表。
- 先确认审稿针对哪个版本：已经移入正文的同会话对照、已删除的附录、已经存在的导航表，不按旧意见再重复添加。
- 旧 CPU 图的实际输入，与仓库中另外存在的测试，是不同事实。修改文字时写清“图中前沿使用哪些记录”，不能悄悄把新日志并入分母，却继续引用旧图的倍数。
- 将代数等价、FP32 分数逐位一致、短名单集合相同、排序相同、最终 ID 集合相同分开。有限次测试也不能写成“调度从不改变结果”。
- 质量风险先于速度收益。平均召回、分位数、最大损失和失败频率有不同含义；预算中位数与质量均值不必对应同一个固定预算。全配置的平均加速与满足同一质量门槛的子集平均分别报告。
- 同一留出池重复 500 个 batch 的测量只验证稳定工作负载的摊销。4–9 batch 的 OpenAI 回本属于 128 查询校准；全池策略的对应时间更长，不能混写成所有校准的回本范围。
- 将索引冷态构建、输入页已缓存、会话首次读文件和完整进程可搜索时间分清。显存比例明确是否扣除 CUDA 上下文、是否含工作区，以及对照是否仅统计索引分配。
- 记录异常时区分“跨二进制输出转储一致”和“同一基线不同进程召回变化”；缺少中间状态时不根据前一项替后一项定位根因。
- 特定 pilot 的合并召回差距不能扩大成完整阶段损失分解。若要分别归因路由、主码截断和重建，记录所需的固定查询、固定候选与逐阶段 GT 覆盖实验。
- 审计计数、原始文件名和排错过程优先保存在审核记录；影响解释或复现的定义集中到协议。保留全部图表数据，不为删减日志式句子而隐藏决定结论的对照条件。
