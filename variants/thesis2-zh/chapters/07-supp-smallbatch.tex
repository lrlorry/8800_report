\subsection{小 batch 改变竞争区间}
\label{sec:7-smallbatch}

batch 为 8、召回率为 0.97 时，CAGRA fp32 在两种估计器下都快于全部四个数据集的 JHQ。较低召回率时 JHQ 仍有竞争力，但接近持平的比较依赖如何使用实测端点。小 batch 研究在四个主比较数据集上，以 batch 为 8、32 比较调度 JHQ、CAGRA fp32／int8 和 IVF-RaBitQ。五轮同步主机到主机测试分别使用 1,000、992 条查询。1,808 个测量包含单 block JHQ 对照；IVF-PQ 和暴力搜索不在这项研究中。

召回率 0.97 时，插值得到的 JHQ／最快对手比值，batch 为 8 时为 0.641--0.893，batch 为 32 时为 0.622--1.008。OpenAI-3072 在 batch 32 的实测阈值下有利于 JHQ，而 Vogue 在 batch 为 8、召回率为 0.95 时的领先依赖插值（\cref{tab:7-smallbatch}）。

召回率 0.90 时，包含达标端点的插值在 batch 为 8 时有利于 JHQ，比值为 1.032--1.479；严格阈值却只有三个胜出。batch 为 32 时比值为 0.866--1.166，严格阈值只有一个胜出。调度在召回率 0.95 时相对单 block 提升 $1.7$--$3.3\times$，改善 JHQ 执行，但不能保证跨系统领先。

边界包含接口成本。仅含传输和同步的空调用中位数为 0.012--0.072\,ms，搜索计时保留了这一成本。CAGRA 使用 Python，JHQ／RaBitQ 使用 C++；预热约定见 \cref{sec:a-t4-t5}。
