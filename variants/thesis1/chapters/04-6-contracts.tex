A 32-bit $n_td$ overflow at $2^{31}$ zeroed primary scale; a version-blind cache reloaded it. Chunked double-precision norms fixed the fault. Successful routing alone is insufficient validation.

\subsection{Completed representation evidence}

The 13 October pilot exported full cached layouts for Vogue (932,328 rows), arXiv (2,253,000) and OpenAI-3072 (999,000).

Codebooks passed separability, scalar-level and sorting checks. An FP64 loop checked $\gamma=2\langle\widehat p,\widehat r\rangle$ on every exported row; maximum absolute error was $1.28\times10^{-7}$--$2.77\times10^{-7}$. Sampled GPU-returned
top-10 scores have maximum relative errors from $2.38\times10^{-7}$ to
$4.85\times10^{-5}$, using $|s_{\rm GPU}-s_{64}|/s_{64}$ with the
query-norm constant included. These are checks of the exported
representation, not re-encoding from the original input vectors.


Across seven workloads and 896 query instances, the pilot additionally
checked the proposed residual bounds against FP64 reconstructed distances
for 72,800,590 routed candidate instances, with zero reported violations.
The same population supports the FP64 composite-score identity check.
GPU-returned-score checks cover only top-10 slots and skip IDs absent
from the routed map, leaving output membership incompletely checked.

Encoder, primary/residual training and construction sources match the
evaluated implementation after namespace normalisation and removal of
the export method. This source
correspondence covers the shared path, leaving later model identity and
large-dataset two-pass construction to separate checks.
