OpenAI/BGE/Stella preparation removes non-finite rows, normalises norms above $10^{-12}$ and samples queries without replacement using seed 42. Stella supplies 999 corpus-sampled queries, not its separate 65-query benchmark. These exports test vector neighbours, not relevance labels. The OpenAI exports share the sampling rule; checks support row alignment on all queries and 10,299 base rows, without original-ID joins (\cref{sec:7-precision,sec:7-2}).

All methods in a cell read the same query and GT files. Ground truth is
computed by exhaustive squared-L2 search over exported FP32 vectors; the
streamed converter maintains top-$k$ across database tiles. Evaluation uses
stored GT order, including its floating-point tie choices. With
$\mathcal T_k(q)$ the first $k$ GT IDs and $\mathcal R_k(q)$ the returned
ID set,
\begin{equation}
\Recall@k=\frac{1}{|\mathcal Q|k}
\sum_{q\in\mathcal Q}|\mathcal R_k(q)\cap\mathcal T_k(q)|.
\label{eq:3-recall}
\end{equation}
GT rows are 100 wide for Vogue/arXiv and 20 wide for the other four;
only ten entries are scored. Duplicate returned IDs do not earn repeated
credit. Range, duplicate and repeat-call checks are recorded separately.

JHQ uses $M=d/8$, $B=B_r=8$, eight coarse iterations and 100,000 residual-training rows. Sweeps reuse trained states but re-encode the database; cold builds start afresh. Training uses database rows. Even/odd query positions give calibration/held-out pools of 500/500, or 500/499 for Stella.
Seeded subsamples of sizes
32, 64 and 128 are drawn 64 times per cell; FULL uses all 500 calibration
queries. GT labels enter the offline oracle and held-out assessment, while
the deployable agreement rule uses search outputs
(\cref{sec:6-2,sec:a-budget-contract}).

Preparation code and shape logs establish this protocol; complete historical
vector-file and trained-state hashes are unavailable.
