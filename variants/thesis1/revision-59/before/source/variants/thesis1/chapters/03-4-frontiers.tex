The competing families cover graph traversal (CAGRA fp32/int8),
product-quantised IVF and GPU IVF-RaBitQ \cite{cagra,pq,ivfrabitq}.
FP32 GPU brute force provides an exhaustive-search reference. Each family
sweeps its own implementation parameters (\cref{tab:3-grids}); the recorded
index configurations can differ in storage and reconstruction fidelity.
Consequently the main frontier measures achievable speed at a quality
target within these grids. A separate memory account accompanies it.

A point dominates another if recall and QPS are both no worse and one is better. The frontier can span index configurations. At target $r$, the measured estimate is
\begin{equation}
Q_{\rm meas}(r)=\max\{Q_i:R_i\geq r\}.
\label{eq:3-measured-frontier}
\end{equation}
It is undefined without a qualifying point. For adjacent frontier points, interpolation uses
\begin{equation}
\log Q_{\rm int}(r)=(1-\lambda)\log Q_a+\lambda\log Q_b,
\qquad \lambda=\frac{r-R_a}{R_b-R_a}.
\label{eq:3-interpolated-frontier}
\end{equation}
The parser first accepts a point within $5\times10^{-4}$ of the target; otherwise it interpolates inside the measured range only. T5 also keeps qualifying measured endpoints below a method's minimum frontier recall. We report both estimates near ties; neither matches storage budgets.

Failures and invalid outputs stay outside the valid frontier. Repeat-call set and order changes are logged separately. Isolated reruns replace contaminated builds; skipped Stella batch-1,000 runs supply no points (\cref{sec:a-e1-protocol}). Current frontiers include int8 CAGRA (\cref{fig:7-frontiers}); historical ADC/poster plots retain their original scope.
