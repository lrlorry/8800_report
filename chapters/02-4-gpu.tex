CUDA groups threads into blocks and 32-thread warps; registers, shared
memory and global memory expose different reuse scopes
\cite{cuda_programming_guide}. JHQ maps primary scanning across neighbouring
candidates for coalesced loads, and refinement across one survivor's
coordinates. Extra blocks can hide latency but duplicate LUTs and buffers;
register/shared-memory use limits residency. These competing costs motivate
the mappings evaluated in Chapter 5. Bandwidth or cache attribution would
require counters beyond throughput measurements.

Selection must be designed with scoring. Faiss uses warp-oriented selection
\cite{johnson_gpu}; bitonic, radix and merge primitives offer different
state/work trade-offs. AIR top-$k$ and GridSelect address workload-dependent
global selection \cite{gpu_topk}. JHQ uses these established ideas for
routing and survivor retention.

CUDA Graph replay reduces launch setup, while capture and workspace changes
belong to the execution lifecycle. Shared-bound admission additionally needs
the ordering and whole-key-access contracts of Chapter 5. Neither a correct
scalar score nor device-only profiling establishes end-to-end correctness
or host-visible performance.
