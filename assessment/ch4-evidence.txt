2. 逐项核对
------------
4.1：train / add / search 三阶段分开；缓存仅保存训练模型，不是完整
可搜索数据库；一次成功 add 后再次 add 被拒绝。查询使用 host-to-host
边界，工作区与 CUDA graph 属于执行状态。

4.2：CPU Gaussian -> LAPACK QR 生成方形 Pi；GPU GEMM 应用旋转，维度
不变。主码解析构造在 CPU，IVF／残差拟合可走 GPU，不笼统称全 GPU。
sigma^2 为样本平方范数均值除以维度，不称为任意数据的精确正态性。
主码／IVF 样本大小依运行脚本；残差为独立的 100000 行步长样本。
固定步长与固定随机种子不是 IID 采样保证。主码先编码，IVF 拟合在
残差码本拟合之前；残差相对主码重建，不是 IVF 中心。
源码有 int8／FP16 辅助分配及 FP32 重算；不能因中心存成 FP32 就声称
所有训练 arithmetic 均为 FP32。归档冷日志未提供实际分配精度轨迹。
冷日志包括 Stella 的 residual CAP at 2000，不宣称精确收敛。

4.3：按 assignment 和输入行号 sort_by_key；lower_bound 形成 offsets。
rho 是最终位置到原 ID 的置换；同列表排序不保证跨构建稳定。两遍
建库的逆映射为临时数组，不虚构常驻双向映射。
主码中间字节为 m*N+p，最终 word 为 4*(j*N+p)，四字节对应同一向量
四个子空间。残差保持 [N,b_r]；四比特偶数维在低 nibble。ID、主码、
残差、correction 必须共同重排，correction 为 2<primary,residual>。

4.4：每向量 M+ceil(d*Br/8)+8 字节，不含模型、offsets、workspace、
context。d=768/1024/1536/3072 时为 872/1160/1736/3464 字节；仅编码
9d/8，不将它当作完整实测 device usage。可选残差 LUT 单独列出。
调小 alpha 不释放整库残差，scratch 也可能保留历史容量。graph 复用
仅在相应配置保持有效时成立，正文限定固定 k，未声称任意可变 k API
都已做完 graph-key 审计。
缓存 key 是参数与步长抽样 FNV，不是全库加密哈希。构造器先创建 Pi，
再进入 train 检查缓存，因此 cache hit 也不等于没有初始化成本。

4.5：分批 H2D + 旋转控制 float staging，压缩索引仍需全库常驻。
一遍保存输入顺序码后 gather；两遍先分配／排序，再重读输入、旋转／
编码并 scatter 到最终位置，以额外遍历换取较低临时压缩存储。
Stella 的原始冷日志确实选择 two-pass；打印 41.6 GB，源码按 2^30
换算，正文规范为 GiB。该值来自 N*(2*b_r+3*M+20)+2^30 的启发式，
不是 measured peak；30.6 GiB 为该日志的尾部可用值，不是峰值余量。
大规模成功记录为 BGE 10091524、Stella 17776615，均 d=1024。
沿用第 7 章的 1.01--10.40 s train+add 和 11.93/20.44 GiB 常驻样本。
尊重成功 CAGRA int8 复验，不从更早失败尝试推断它放不下。

4.6：区分 source-derived 不变量、实际表示检查、独立 FP64／CPU 参考、
算法选择和 sanitizer。代码有尺寸、码本可分离性和排序等前提检查；
尚未找到足以宣称完整 C0/C1 独立编码／置换验证已完成的记录，正文
和原待补实验文件均明确记缺口，不用 recall 或查询 sanitizer 替代。

3. 本轮新增的计时边界澄清
------------------------
demo_jhq_batch_pipeline.cu 先构造 idx、准备样本，再启动 train() 计时。
JLTransform 在 idx 的初始化列表里做 QR；构造器还建立 cuBLAS 并预热。
因此原 train+add 数字排除对象构造、主机 QR、构造器库预热和样本准备，
也排除原始文件读取及后续调度校准。数字保持原样，在第 4、7 章及
附录同步说明，待补清单加入这些分项与整体冷启动计时。
不把 source/harness 时序核对冒充 measured binary 的完整身份认证。
