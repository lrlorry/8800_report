一、编号意见逐项结论
====================

1. K_LOCAL、默认 exact_topck 和最终 top-k
结论：成立，原稿事实错误，已更正中英文。
证据：jhq_v69_probesel/search.cu 的 exact_topck() 默认返回 true，只有
JHQ_EXACT_TOPCK=0 才选择旧的局部有损保留路径。最终
batched_topk_final_kernel 对全部 ck 个候选反复取最小值，按数据库 ID
打破并列。历史 d5e1526（v69）与 bf31b41（v57）的源码也具有这些行为。
原稿把“源码中存在 K_LOCAL=4”误当成“被测默认路径使用 K_LOCAL=4”，
且把主码保留与最终 top-k 选择混淆。这是需要承担并纠正的实质错误。
处理：7.5 改为默认精确主码 top-c 与精确最终选择；7.8 删除
“approximate final selection”。保留固定评分、嵌套候选、共同全序等
单调性条件，以及 G=0 截断并列和跨批大小路径变化的限制。
不能把“默认精确”进一步写成所有配置无条件单调；2,304 次一致仍是
该网格、该样本决策的实证，不是留出 recall 保证。

2. Vogue 异常定位
结论：主要成立，但“与 probe 绝对无关/只能是某个残差内核”应收敛。
证据：id_vogue-768_v65.json 在 b=8/1000 报 0.9642；同一基线二进制的
两次 timing JSON 在相同的完整 1,000 查询池上均报 0.9644。
注意 b=32/256 使用截断查询池，不能混进跨进程 recall 统计。
G=1、b=8 的两版本 probe/primary dump 记录有相同 SHA-256，覆盖 1,000
查询；原始 dump 二进制不在本地证据包中，因此这里验证的是归档的
比较结果和哈希记录，不声称重新计算了服务器二进制 dump 哈希。
处理：7.4 写明波动不需要 probe 改动即可发生；在受 dump 控制的用例中，
差异位于记录的 primary 边界之后。残差表示、输入或评分计算等仍是
可能来源，根因未确定；不把局部 dump 覆盖升级成全部计时路径的证明。

3. 369 与 401
结论：口径说明建议成立；369 本身没有算错。
重算结果：A 重复调用 deterministic=false 为 369；B 与 A 不一致为 367；
两者并集为 401，交集为 335，只有 B/A 标记增加的点为 32。
处理：7.8 同时解释两种口径。B-versus-A 是跨协议相等性检查，不能称为
“重复调用 B 时非确定”的测试。

4. 减少调用次数只发生于慢点
结论：成立，已改。
重算结果：274 个点 calls_per_round<24，其中最大吞吐为 507,519 QPS。
规则确实使用包含首次调用的预热区间；Python 基线程序的该区间还包括
首次结果转换、recall 与 ID 检查，不是纯稳态调用延迟。
处理：7.1 说明实际自适应调用预算；附录 A 给完整实现边界。

5. α=100 偏弱，应增加 α=64
结论：核心建议成立；Claude 的两处附带概括需要纠正。
重算 rule/α64：几何平均 1.0544599；范围 0.8212114--1.3665069；9/12
个单元更快。两种固定预算均在 10/12 单元达标，失败均为 arXiv。
但 α64 的最差损失为 0.0050，α100 为 0.0016，不能把“同样十个达标”
当作完全相同质量。预算表已增加 vs 64 列。
“OpenAI 仍有 1.23--1.37 倍”不覆盖全部四个 OpenAI 单元：
OpenAI-3072/512 为 1.052118，所以完整范围是 1.052--1.367。
“arXiv 的 40/64 次超标损失全为 0.0012”不成立：原日志 p95_loss=0.0024
直接否定这一说法；α64 自身的损失也为 0.0024。没有逐 draw 明细时不
重建唯一分布。可以确认的是默认 α100 自身在 probes128/512 分别损失
0.0012/0.0016，而 rule 的平均损失均为 0.0009。
处理：7.5 区分 oracle-relative 超标与相对默认质量变化；增加 full-pool
校准成本 9.5--60.3 ms。
回本重新绘图：对 α100 为 2.4--55.4 批；对 α64 为 5.7--404.3 批，
都是有利单元中的估计。Vogue/512 对 α64 不回本。不能用对弱基线的
17 批回本替代 Vogue/128 相对 α64 的约 404 批。

6. 缺 E1 显存比较
结论：成立，已补表和解释。
JHQ 进程总量减 507.2 MiB context、仍包含 workspace；CAGRA 为构建时
index allocation delta。重算范围（GiB）：
Vogue：0.90--1.01 vs 2.89--2.91；比值 0.31--0.35。
arXiv：2.01--2.19 vs 6.84--6.98；比值 0.29--0.32。
OpenAI-1536：1.79--2.33 vs 5.95--5.97；比值 0.30--0.39。
OpenAI-3072：3.54--3.82 vs 11.67--11.68；比值 0.30--0.33。
处理：7.7 新表明确不同口径、参数扫范围、没有严格匹配 recall，也不是
构建峰值或相同显存预算。“约三分之一”可作近似观察，不能省略口径。

7. int8 最高 recall 与胜出区间
结论：成立，已补；速率范围统一标注估计方法。
最高实测 recall：0.9453、0.9620、0.9667、0.9683，均无 0.97 合格点。
0.90/0.92 的 int8/JHQ 插值比为 1.1985--1.9777；实测阈值比为
1.3943--2.0620。因此 1.2--2.1 是混合精度的概括，不一定错误，但正文
统一用同一插值规则报约 1.20--1.98。arXiv/0.95 和两个 OpenAI/0.94
仍由 int8 领先，已明确写入。

8. 大数据集加数字
结论：部分采用；Stella 的统一同 recall 速率结论不能照抄。
BGE 在共同目标 0.88/0.90/0.92/0.94/0.95，int8/JHQ 为
约 1.35--2.96；在 int8 的最高实测 recall=0.9579 处，JHQ 插值比为
1.0860，可约写 1.09。若目标写成 0.958，则相同容差规则给 1.0834，
精确值随目标/近点约定而变，正文采用明确的 0.9579。
Stella 的 JHQ 最低前沿 recall=0.978679，int8 最高=0.978278，大部分
更高 recall 区间没有共同覆盖。未定义配对点的“高 recall 快1.6--2.8倍”
不能当作统一的 matched-recall 结论。
处理：写出一个透明实测对：JHQ 185.4k QPS@0.978679，int8
66.3k QPS@0.978278，速率比 2.80，但 recall 略异。更高 recall 的 JHQ
点也可能更慢，不能声称全部支配 int8。

9. 大 batch 机制缺少阶段数据
结论：成立，已补。
v62 arXiv b1000：α100 scan 2922.3165→6079.3205 μs；α200
3529.879→7651.937 μs，后者 merge 2623.8845 μs。
v63 同次 paired profile 的 α200/G8：scan 7968.405→5513.235 μs，
merge 2628.674→470.9575 μs。
处理：7.6 增加数值；批大小图右侧改为 b8 与 b1000 的 scan+merge 柱图。
不把 v62 和 v63 两次 profile 的数值混为同一次配对测量。

10. Amdahl 定量检验
结论：应加定量检验，但原意见的分母不适合端到端上界。
59%/24% 来自 refine/(scan+refine+topk)，未计路由、其他阶段和主机成本。
三阶段比例的准确值约 0.5888/0.2361，估计约 1.961/1.265；不能把它们
称为主机到主机的理论上界，也不能混用四舍五入后算出的 1.97/1.27。
处理：用 baseline kernel refine 时间除以 baseline wall latency，比例为
0.5292/0.1676，按 1/(1-f+f/s) 得 1.787/1.175，接近实测 1.789/1.171。
这混合独立 profile 与 wall-time 测量，只是解释性估计，不宣称严格上界。

11. 三项缺口
结论：建议成立，已补，但异常与历史结果必须限定。
(a) 在 median call<10ms 的 RaBitQ 配置中核查了 30--60ms 长调用，
没有把所有慢配置中的 30--60ms 都当作“异常”。敏感性重算按
10^6 / median(call_ms) 得 QPS；0.97 的 JHQ/RaBitQ 比为
1.063、0.995、1.118、1.100，三个优势与 arXiv 接近持平保持。
(b) 每数据集所有 RaBitQ 配置的 median((max-min)/median QPS) 为
3.79%、3.34%、2.87%、5.25%。这不是 matched ratio 的置信区间。
(c) 历史 v57/bf31b41 日志重算：10/12 更快；1.054--2.773 倍；
校准 5.2--30.8ms。与新版分开报告；“精排更快可能缩小可节省空间”
是与观测相容的解释，不是已经隔离验证的因果结论。
