三、按 7.1--7.8 对照新版
=======================
7.1 来源说明：仍应补访问层级。新版附录已有组件、运行头、程序和
    原始路径映射；缺失的 binary/index 身份仍明确保留为未知。
7.2 外部基线：新版已经并列插值与达到阈值的实测比较，保留 int8
    低 recall 优势、RaBitQ 高 recall 优势和 arXiv 近似持平。
7.3 LUT/packing/refinement：建议成立；新版区分历史单次汇总与重复
    测量，并修正了上一轮 Amdahl 分母问题，未将所有收益乘在一起。
7.4 正确性矩阵：值得采纳的呈现建议，但现有三个小节已经分别解释
    primary top-c、完整评分后的共享界、centroid probe 的契约与
    覆盖范围。汇总表可以提高可读性，本身不增加任何正确性证据；
    不应仅因少一张表就认定技术论证错误或课程硬性不合格。
7.5 预算：新版还增加 fixed 64，比旧附件更完整。相对 64 是 9/12
    更快、几何平均 1.05446；回本上限升至 404.3 batches，并有
    无法回本的单元。附件只报相对 100 的 2.4--55.4 范围并非算错，
    但已经不足以代表新版全部预算结论。
7.6 调度：收益分母、不同 batch 的单元数量和非 oracle 的 regret
    限制仍成立；新版已经保留。
7.7 构建/内存：新版保留成功隔离重测的 Stella int8，区分未尝试、
    容量估算和旧失败记录；cold build 每集一次，不作显著性结论。
7.8 数值稳健性：新版已加 RaBitQ 五轮范围的描述性统计、以调用中位
    延迟重算吞吐的敏感性检查，以及 369/367/401 的口径说明。
    这部分回应了附件的 near-tie 波动建议，但不是独立重建的置信
    区间，也不是重新训练多次的统计比较。

四、这份意见没有发现的旧版实质错误
==================================
旧稿把默认路径的选择误说成近似最终选择。当前默认 exact_topck() 为
true；JHQ_EXACT_TOPCK=0 才选择旧有损 primary retention 路径，最终
top-k 扫描全部 ck 候选并按 ID 处理并列。本轮再次用 git show 检查了
实际预算历史头 d5e1526 和 bf31b41 的默认设置，结果相同。

所以不能因为 GPT 对旧章总体肯定，就撤销上一轮根据代码做出的修正。
默认精确是阶段语义：仍不等于原空间 exact kNN，也不自动证明持出集
recall 对所有预算/批大小单调。相关完整分析见 ch7-review-response.txt。
